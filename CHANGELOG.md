## [0.3.0](https://github.com/danielcopper/emu-atlas/compare/v0.2.0...v0.3.0) (2026-08-20)


### ⚠ BREAKING CHANGES

* the sealed EmuDeck vector's catalogue expectation gains the emulator-list-derived statement and its coreless fixture's enumeration honesty (info-path-unresolved); the vector validator now permits entries beside a no-catalogue code exactly when emulator-list-derived rides with them.
* the launchable contract gains an `alternatives` field (empty outside the entry-not-accepted verdict), so every existing launchable expectation gains the key; the `an-accepted-extension-is-launchable-with-its-entry` fixture additionally carries its core now, and its answer confirms the claims instead of stating them unestablished.
* the vector 'retrodeck-firmware-a-broken-catalogue-file-claims-nothing' now guarantees the catalogue-invalid finding with system-unknown instead of emulator-catalogue-unreadable — a truncated bundled es_systems.xml is a file ES-DE refuses to load on, not one whose content is merely unknown.
* **saves:** the flycast shared-mode vectors' granularity readings grow by the four slot-2 switches — every answer in that mode now states them, with their live values or null where nothing establishes one.
* **saves:** the vector 'a-standalone-entry-answers-the-texture-question-and-refuses-the-save-one' now shows the refusal on an emulator without a save card (Azahar) — Dolphin's gc entry answers its save question instead of refusing it.
* **saves:** the mame card's mode 'disabled' is renamed 'frontend-paths' and its 'enabled' mode is gone — a paths-on machine now answers with no granularity mode and structured caveats (save-root-unresolvable / save-root-redirected / core-mode-unestablished) instead of a per-game-file claim; the vector 'three-trees-one-save-and-one-of-them-cannot-be-named' now registers mame_read_config and guarantees the renamed mode.
* **screenshots:** the role vocabulary gains 'notes', the machines-family vector 'an-arcade-build-states-two-directories-it-cannot-list' now guarantees MAME 2010's nine-group answer, and the file-names-unestablished caveat message is reworded neutrally (prose only).
* **saves:** the file-set-spans-roots caveat's data now carries 'dir' and 'files' (the resolved part) instead of 'also_under', the 'VMU A1' mode guarantees a declared file set with cross-root groups instead of an unknown one, and the machines-family vector
* **saves:** every granularity alternative in the vectors replaces its 'value' string with the 'values' list (the old value is values[0]), and the machines-family vector 'multi-option-core-names-the-options-that-decide-granularity' now guarantees NeoCD's record-plus-caveat answer instead of SwanStation's.
* **saves:** two machines-family vectors are renamed and now guarantee card answers instead of the multi-option degradation ('a-cartridge-with-battery-ram-names-one-file-across-ten-systems' → 'a-cartridge-fills-the-frontends-interface-through-the-card', 'a-cd-system-where-the-interface-claim-was-unreachable' → 'a-cd-system-answers-with-the-cores-own-bram-tree'), and the multi-option showcase vector re-anchors on pcsx_rearmed.
* **saves:** the granularity block's shape changed in every vector that carries one — `option_key`/`option_value`/`options_file` are replaced by `mode` and `readings`, and `alternatives` entries are objects naming the mode, the option combination and its granularity. The machines-family vector 'multi-option-core-observes-its-core-written-file-set' is renamed to 'a-rule-card-observes-its-three-role-files' and now guarantees the card answer instead of the multi-option degradation, and `granularity.value` may now be `"none"` (a mode that keeps no save at all).
* **saves:** the machines-family vector 'an-option-that-moves-the-writes-into-the-image-itself' now guarantees the declared emptiness plus the save-inside-content caveat instead of declaring the content file as a save, and 'a-disk-diff-that-spells-the-frontends-name' carries the enabled mode's granularity alternative as per-game-file (the content file) instead of per-game-files.
* **saves:** two machines-family vectors changed their guarantees with the corrected audit data — 'standard-dir-core-observes-its-core-written-file-set' (renamed 'multi-option-core-observes-its-core-written-file-set') now carries the core-multi-option caveat naming Beetle Saturn's two sharing options, and 'the-one-ds-core-that-uses-the-interface-names-its-file' no longer carries core-unaudited, because melondsds is audited now.
* **saves:** the machines-family vector 'a-core-that-fills-no-memory-id-says-so-and-says-what-stays-open' was re-keyed from desmume to bluemsx — the desmume fixture's guarantee (declared-empty file set with core-own-writes-unestablished) is superseded by the desmume card, which declares `<rom_stem>.dsv` for the same machine.
* **saves:** the vector proving that a second-choice core states a declared emptiness ran on FB Alpha 2012, which now carries a card and states files instead. It moves to DICE, an arcade alternative that still has that shape. A savefile answer for any of the four FB Alpha 2012 builds now states files where it stated `unknown`, and the parent's answer changes from a declared emptiness to a declared file set.
* **saves:** a savefile answer for the current MAME now carries a `filenames-content-conditional` caveat it did not before, naming the class of content its file list was established for. Nothing about the files changes — the names, directories and groups are the ones it already stated — but a client that treats an unexpected caveat as a reason to distrust the answer will see one more. It is a scope, not a degradation: the list is exact for a romset whose file stems are spelled as MAME spells the driver.
* **saves:** `file_set.groups[].files` is now `tuple[str, ...] | None`, `null` in the serialized contract. A client iterating a group's files must handle `None`, which means "the directory is stated and its names are not" — take the directory whole. No name moves and no directory disappears: the answers that change gain a group they did not have, and `file_set.files` and `placement.dir` are untouched. One vector changes with it, MAME's, which gains its `diff` group.
* **saves:** a savefile answer for bsnes, bsnes-hd beta or bsnes-jg now states a declared `<rom_stem>.srm` and `<rom_stem>.rtc` where it previously stated whatever happened to lie in the save directory under the content's stem, or nothing at all, and it carries a `granularity` where it carried none. The names do not move — they are the ones these cores were already writing — but the second one is new to the answer and the claim is a declaration rather than an observation, so a client branching on `state == "observed"` must add `"declared"`. One vector's fixture changes with it: the case that proves an unread core states no file set can no longer use bsnes, and runs on `snes9x2005` instead.
* **saves:** `savefile_location` asked **without** a system now states file names for any core whose record covers several systems that agree — 65 of the 66 recorded cores — where it previously answered `unknown`. Thirteen vectors change. The new answers carry `file-set-across-systems` naming the systems they hold for; a client that treated `unknown` as "atlas has nothing" and fell through to its own table should prefer the answer, and one that treats a declared set as universal must read that caveat's `data["systems"]`. Where a core's systems disagree, and wherever a system is named, the answer is unchanged. The `system=` parameter itself is purely additive.
* **saves:** a savefile answer for Virtual Jaguar changes on `atarijaguar`. `file_set` becomes a declared `<rom_stem>.srm` and `<rom_stem>.cdrom.srm` where it was `unknown`, `granularity` and `file_set.groups` are stated where they were absent, and the answer carries `unverified-version` because no arrangement has confirmed this build. Three vectors change accordingly. A client that fell back to its own table for this core should stop: the second file is one such a table is unlikely to have known about.
* **saves:** a savefile answer for MAME changes on every system it is launched for. `dir` moves into the core's own `mame/nvram` subtree, `file_set` becomes a declared file where it was a declared emptiness, `granularity` and `file_set.groups` are stated where they were absent, and `core-own-writes-unestablished` is replaced by the concrete answer. Clients gain one caveat code to know: `file-names-unestablished` means a directory holds save data whose names atlas will not state — copy it whole rather than by name.
* **saves:** a savefile answer for FinalBurn Neo changes on every system it is launched for. `dir` gains the core's own `fbneo/` subtree, `file_set` becomes a declared `<rom_stem>.fs` where it was a declared emptiness, `granularity` is stated where it was absent, and `core-own-writes-unestablished` no longer rides along — the writes are established now. A client that read the empty set as "nothing to fetch through RetroArch's naming rule" was right then and is wrong now; there is a file, and it is in a directory one level below the one the answer used to name.
* **saves:** every savefile and savestate answer's `file_set` carries a new `groups` key, and the vector corpus states it. Nothing that was in an answer moved or changed value: `groups` is empty on every observation, every unknown and every standard-rule declaration, and where a card populates it, `dir`, `files`, `complete` and `granularity` are what they were. A client reading the fields it already read needs no change; one validating the shape exactly must accept the new key. `Granularity.value` gains `shared-file`, so code matching that vocabulary exhaustively must handle it — no shipped card selects it yet.
* **saves:** a savefile answer for a core on a system it does not lead now reports `file_set.state == "declared"` where it previously reported `"observed"` or `"unknown"`, and carries a `granularity` where it previously carried none. One vector changes; its `files` list is identical before and after.
* **saves:** a savefile answer for Snes9x asked through the catalogue route now reports `file_set.state == "declared"` with both `<rom_stem>.srm` and `<rom_stem>.rtc`, where it previously reported `"observed"` with whatever lay in the directory, and it carries a `granularity` where it previously carried none.
* **saves:** for a core with a save-memory record, a savefile answer asked through the catalogue route now reports `file_set.state == "declared"` where it previously reported `"observed"`, and carries a `granularity` where it previously carried none. Four vectors change accordingly; `files` is identical in all four.

## [0.2.0](https://github.com/danielcopper/emu-atlas/compare/v0.1.0...v0.2.0) (2026-08-12)


### ⚠ BREAKING CHANGES

* **oddities:** on a machine whose libretro core states no default for the option a rule card hangs on — the probe reads no registration at all, or reads the key with no default declared — and whose configuration states no value for it either, the card no longer applies. Such an answer used to carry the card's recorded default and its placement; it now carries the standard placement, no granularity, and the caveat `core-option-value-unestablished` with the core and option keys. Cores that register the option *with* a default — every one observed on a real installation so far — are unaffected.
* **placement:** card-generation-mismatch is now core-generation-mismatch, and the data key card is now core on every caveat that carries it (core-generation-mismatch, unverified-version, unknown-option-value, file-set-spans-roots, filenames-unverified, filenames-content-conditional). card-mode-unconfirmed is withdrawn: after this change nothing can emit it. savefile_location and savestate_location now return a placement or an Unresolved on every route, and answer core-not-installed for a core the installation does not have, where they previously answered a directory. Answers about a core that is present and unreadable no longer apply that core's recorded save behaviour — the directory, the granularity and the sources become the standard ones, and core-generation-unestablished says why.
* **retrodeck:** machines whose Flatpak override files name XDG_CONFIG_HOME or HOME answer differently. The rom_location and roms_dir refusals for the unset default and the ~ expansion now resolve against the pinned config home; the config-home-relocated rider disappears from every RetroDECK answer (the code remains on EmuDeck's portable.txt rider); and a ~ in retroarch.cfg values expands against the override's effective HOME where one stands. The retired refusals asserted the on-disk tree might not be the one in force — the pinned flatpak source proves it is.
* **evidence:** answers from emudeck installations no longer carry the arrangement-unverified caveat; on a machine whose backend checkout names a commit other than the verified record they carry arrangement-version-drifted instead.
* **placement:** a RetroDECK machine whose ROMDirectory is ~/Emulation/roms — the fixture of the former rom-location-refuses-a-romdirectory-that-is-not-an-absolute-path vector — now answers the expanded directory under the per-app config home with no caveat, where it answered no directory with rom-path-unresolved. The refusal was atlas being stricter than the frontend: ES-DE really launches from the expanded directory, so a client keying on the stable refusal sees an answer instead.
* **emudeck:** on an EmuDeck arrangement with ES-DE evidence on disk, firmware_for_system no longer answers the derived enumeration with emulator-catalogue-unavailable — the catalogue answers, and the caveat becomes emulator-catalogue-sealed (with firmware-declaration-unknown for a system the readable layers do not declare) or emulator-catalogue-unreadable for a broken resource shadow. Machines without ES-DE keep the old shape.
* **firmware:** firmware answers speak ES-DE system ids everywhere. The libretro-derived slugs (dc, gg, pce, sms, lynx, cdi, palmos, mac68k, c128, _arcade, _engine) are no longer produced or accepted - querying one answers empty with system-unknown. Requirement rows' system field and the assignment caveats' table_version data changed accordingly, and the new caveat code system-not-in-catalogue marks systems no ES-DE build declares. The own spellings (bk, ti83, ep128) became valid question words on every route: firmware_for_system now answers them with their filed rows plus system-not-in-catalogue on catalogued and catalogue-less arrangements alike, where they previously answered system-unknown (catalogued) or emulator-catalogue-unavailable (catalogue-less).
* **api:** the save-family names are renamed, old -> new: save_location -> savefile_location and state_location -> savestate_location (Installation protocol, EmulatorEntry, EveryInstallation); entry_save_location -> entry_savefile_location and entry_state_location -> entry_savestate_location (the entry routes); SavePlacement -> SavefilePlacement; placement_contract -> savefile_placement_contract; build_save_placement -> build_savefile_placement; vector input keys query -> savefile_query, state_query -> savestate_query, entry_query -> entry_savefile_query, entry_state_query -> entry_savestate_query; aggregate question names save_location -> savefile_location, state_location -> savestate_location.
* **placement:** RetroArchCfg now names the family it resolved, and its family-specific fields lost their savefile prefix — savefile_directory is directory, savefiles_in_content_dir is in_content_dir; LayoutDefaults follows. resolve_save_layout is resolve_layout and takes a required keys argument. The conformance vector contract is unchanged and additive.
* **catalogue:** RetroDeck.roms_dir() returns str | None and resolves ES-DE's ROMDirectory instead of retrodeck.json's roms_path; the per-game-override anchor follows the same setting; a wrong-typed roms_path no longer yields marker-invalid health findings; the per-game-selection vector's fixture was corrected to a machine that can exist.
* **evidence:** answers from a verified arrangement whose machine states a version different from the evidence pin now carry arrangement-version-drifted (one existing vector's expected block gains it); on a machine whose marker states an empty version, the per-card unverified-version caveat's data changes from verification "drifted" with an empty arrangement_live to verification "runtime-version-unknown", because empty is the arrangement's own spelling for unset.
* **api:** 65 names are no longer importable from the atlas top level: 62 live in their modules (atlas.machine, atlas.retroarch_cfg, atlas.esde, atlas.core_info, atlas.firmware, atlas.oddities, atlas.evidence, atlas.placement) and RETRODECK_DEFAULTS, EMUDECK_DEFAULTS and interpret_cfg are removed; 19 new vocabulary names join the top level (net 184 → 138); the arrangement classes and kind strings rename to BareRetroArchFlatpak/bare_retroarch_flatpak and BareRetroArchNative/bare_retroarch_native, including in vector installation selectors and evidence data.
* **api:** Python attribute renames (FileSet.provenance, Granularity.option_provenance, EmulatorSpec/EmulatorEntry.provenance; eight CAVEAT_* constant names — code strings unchanged); serialized catalogue entries gain "system" and their caveats serialize as {code, data} objects instead of bare code strings.
* **firmware:** standalone emulators answer declaration "unsupported" with caveat standalone-unsupported on the firmware route (previously "absent" with standalone-emulator); an absent system_directory key resolves to the platform default and answers fully instead of an empty answer with system-directory-unset; the retired codes standalone-emulator and system-directory-unset are refused by the vector validator; a cleared key answers system-directory-cleared.
* **installations:** firmware, catalogue, systems and identification answers from a broken installation now carry the health finding caveats in front of their own; previously only save placements did.
* **contract:** installations[].health serializes as a list of {code, data} finding objects instead of bare code strings; placement answers carry health finding codes directly and the health envelope caveat (code "health" with data["issue"]) no longer exists; CAVEAT_HEALTH is removed from the public API.
* **evidence:** every caveat-bearing answer from an arrangement without a live-verification record (emudeck, standalone_retroarch_flatpak, native_retroarch) now carries the arrangement-unverified caveat; existing vector expected blocks for those arrangements changed accordingly.
* **installations:** emulators_for and systems return CatalogueAnswer and SystemsAnswer instead of bare tuples, on every Installation handle. When the bundled es_systems.xml cannot be read, the answer is the refusal alone — entries a readable custom_systems overlay declared are no longer reported, because on the merged path only the bundled layer decides whether the catalogue was read. (A custom overlay carrying loadExclusive is the catalogue alone and answers without the bundled layer — see [#74](https://github.com/danielcopper/emu-atlas/pull/74).)
* **machine:** Machine.glob returns GlobResult instead of a bare list; ports must implement the explicit outcome and the unlistable fixture state; read_core_declarations returns CoreEnumeration; the machines vector schema is 3.
* **placement:** a card rooted in the system directory no longer emits a system_directory hole; consumers branching on it must handle the resolved answer, and such a placement may now report the content directory as its root kind.
* the per-game VMU mode's expectation changes from an unverified file set to a stated one, and fixture content is renamed in five vectors.
* four vector expectations change. Consumers branching on no-firmware-declaration must handle no-firmware-requirement and firmware-declaration-unknown; the identification caveats now carry the caller's stated size.
* translate flatpak sandbox spellings so the override chain reaches the host ([#31](https://github.com/danielcopper/emu-atlas/issues/31))
* installation.firmware_status() is replaced by firmware_for_core / firmware_for_system / firmware_inventory / identify_firmware. The packaged table is renamed from data/bios_registry.json to data/firmware_hashes.json and no longer carries declarations; atlas.bios is gone in favour of atlas.firmware. The firmware contract shape changed accordingly.
* `CoreInfo` gains the `options` field and the fixture core spec accepts an `options` map; a new caveat code `card-generation-mismatch` joins the contract.
* the machine seam signatures, health representation, vector schema, and several public names changed; the vector contract's expected blocks are re-serialized under schema 2.
* rebuild atlas as a live resolver — machine seam, rule cards, ES-DE catalogue ([#13](https://github.com/danielcopper/emu-atlas/issues/13))
